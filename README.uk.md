# StepVisionKit

Відео-набір для ComfyUI, що веде матеріал аж до фінального файлу:
**професійний вхід** (RAW-фото, відео, HDR-секвенції) → **обʼєкти** (YOLO з трекінгом, вибір кліком, бокси для SAM2) →
**глибина** (DA3 на весь кліп, грейд без мерехтіння) → **лук** (розмиття за глибиною, палітра, серпанок, зерно) →
**реалізм камери** (шум сенсора, ISP, оптика) → **HDR-вихід** (EXR, 16-bit PNG, ProRes, HEVC 10-bit).
Mac (MPS) і CUDA.

У кожної ноди одна картка: превʼю зверху, 3–5 головних налаштувань, решта під «ще».
Категорія в меню: **`StepVisionKit`** → `IO` · `Detect` · `HUD` · `Depth` · `Realism`.

## Ланцюжки: що за чим іде

```
А. Обʼєкт → маска (вирізати людину)
   Load Video · Pro ─images→ YOLO Detect (клік по людині) ─bbox_for_sam2→ Sam2Segmentation ─mask→ Cut By Mask → Save Video · HDR

Б. HUD-рамка над обʼєктом
   Load Video · Pro ─images→ YOLO Detect ─bounding_box→ HUD Sprite (своя PNG-рамка) ─composite→ Save Video · HDR
                                                       ├→ Draw Boxes · HUD (кутики, підписи, сліди)
                                                       └→ Overlay On Boxes (картинка на обʼєкт)

В. Глибина відео
   Load DA3 Model ─da3_model→ Video Depth · DA3 stream ─depth→ Depth Grade (кадр і відео-превʼю в картці) ─depth→
        Depth Look · Video · Camera Realism · Save Depth · 16-bit / EXR · HUD Sprite
   Порахувати раз і грейдити далі без DA3:
   DA3Inference ─da3_geometry→ Raw Depth Save · EXR   …потім…   Raw Depth Load · EXR → Depth Receiver ─depth→ Depth Grade

Г. Лук на фото → той самий лук на відео
   Load RAW · photo ─image→ Depth Look · Full (+ глибина з В) ─grade→ Depth Look · Video (+ кадри й глибина кліпу)

Ґ. Рендер → «знято камерою»
   будь-які кадри ─image→ Camera Realism (+ глибина з Depth Grade, необовʼязково) ─image→ Save Video · HDR
```

YOLO Detect сам віддає `bbox_for_sam2`; `Boxes → BBOX` потрібна лише для чужих детекторів.

## Що всередині

| група | ноди | нащо |
|---|---|---|
| IO | `Load RAW · photo`, `Load Video · Pro`, `Load Image Sequence · HDR`, `Save Video · HDR`, `Save Image · HDR` | RAW з камери і професійне відео на вхід, лінійна або дисплейна крива; EXR / 16-bit / ProRes / HEVC 10-bit на вихід |
| Detect | `YOLO Detect`, `Detect Objects · YOLO`, `Select Box`, `Boxes → BBOX · SAM2` | бокси з превʼю в картці (поріг, класи й кількість міняються наживо, клік обирає обʼєкт); `Detect Objects` додає ByteTrack зі сталим `track_id`, `Select Box` бере один за `track_id`, точкою чи класом |
| HUD | `HUD Sprite · PNG frame`, `HUD Boxes · corners`, `Draw Boxes · HUD`, `Overlay On Boxes`, `Cut By Mask` | своя PNG-рамка їде за боксом (9-slice, дірка у відео, окрема альфа); малювання й вирізання по масці |
| Depth | `Video Depth · DA3 stream`, `Depth Grade · anti-flicker`, `Depth Curve · DA3 → V2`, `Depth Receiver · raw DA3`, `Raw Depth Save / Load · EXR`, `Save Depth · 16-bit / EXR` | глибина DA3 для довгого кліпу в межах RAM, грейд піпетками й кривими в картці Depth Grade, запис і читання глибини |
| Look | `Depth Look · Full / Simple / Video` | розмиття за глибиною, палітра, силует, серпанок, шлейф, ореол, зерно; тюнер у ноді, `auto_run` або «Render final» (див. [depth_look/README.md](depth_look/README.md)) |
| Realism | `Camera Realism` | профілі камер: шум сенсора, байєр, ISP, оптика, серпанок за глибиною; лупа крупняку, `auto_run` або «Render» |

`Depth Grade View · Frame / Video` і `Depth Grade · Live` лишились, лише щоб відкривались старі workflow; вигляди тепер живуть у картці Depth Grade.
**Settings → StepVisionKit → Cards**: сховати превʼю в нодах, колір і підписи боксів YOLO.

## Встановлення

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/steptonite/ComfyUI-StepVisionKit
pip install -r ComfyUI-StepVisionKit/requirements.txt
```

Ваги YOLO кладуться в `ComfyUI/models/yolov8/` (`face_yolov8n.pt`, `person_yolov8m-seg.pt`,
`yolo11n.pt` — що завантажиш, те й буде у випадайці). `torch` ставити не треба, він уже є в ComfyUI.

> **Історія назв.** Раніше це жило двома паками — `comfyui-lex-bridge` і `comfyui-visionkit`, —
> які реєстрували частину ключів ОДНАКОВО: вигравав той, що вантажився пізніше за алфавітом,
> і воркфлоу мовчки брав чужу ноду. Тепер один пак. Внутрішні ключі (`Lex*` / `VK*`) навмисно
> лишились історичними: ComfyUI шукає ноду в збереженому json за рядком `type`, і перейменування
> зробило б червоними всі раніше збережені воркфлоу.

## 🔴 Перед усім: арифметика RAM (8 ГБ на цій машині)

Один **повний батч кадрів** у ComfyUI лежить у RAM як float32:

```
кадрів × висота × ширина × 3 канали × 4 байти
```

| що | 50 кадрів FullHD | 200 кадрів FullHD |
|---|---|---|
| один IMAGE-батч | **1.24 ГБ** | **4.98 ГБ** |
| один MASK-батч (1 канал) | 0.41 ГБ | 1.66 ГБ |

**Кожен увімкнений вихід — це ще один такий батч.** Тому:

- `LexYOLODetect.make_preview = False` на прогоні (інакше +5 ГБ на 200 кадрів);
- `LexHUDSprite.emit = composite` (не `both`), `emit_box_mask = False`;
- прев'ю-ноди (`PreviewImage`, прев'ю всередині `VHS_VideoCombine`) вимикати — вони жеруть
  не лише Python, а й **браузер**;
- 50 кадрів за раз через `Meta Batch Manager` — робочий розмір, перевірено 10.08.

⚠️ Окремо: ComfyUI 0.30 стартує з **`Using RAM pressure cache`**. Це означає, що під тиском
пам'яті він **викидає закешовані результати нод**. Звідси ефект «я лише натиснув Save Output,
а воно перерахувало все з нуля» — кеш уже було злито. Лікується при старті:
`--cache-classic` (агресивний кеш, більше RAM) або `--cache-lru N`. На 8 ГБ радше змиритись
і одразу вмикати `save_output` ДО запуску.

## Нода `YOLO Detect (MPS, клас-агностик)` — `LexYOLODetect`

Ганяє ultralytics напряму на MPS, віддає бокси одразу у двох форматах.

| параметр | що робить | як ставити |
|---|---|---|
| `images` | вхідний батч кадрів | з `Load Video` / `Meta Batch` |
| `model_name` | файл із `models/yolov8/` | `face_yolov8m.pt` — обличчя, `hand_yolov8s.pt` — руки, `person_yolov8m-seg.pt` — людина, `yolo11n.pt` — 80 класів COCO |
| `device` | `mps` / `cpu` | `mps` |
| `conf` | поріг упевненості 0.01–0.95 | 0.25 дефолт. Ловить зайве → підіймай до 0.4. Губить кадри → 0.15 |
| `imgsz` | до якого розміру ужимається кадр ПЕРЕД детекцією | 640 дефолт. 🔴 **на якість вихідного відео не впливає** — це тільки для детектора. Дрібне обличчя в кадрі → 960/1280 |
| `class_filter` | фільтр по назві класу, через кому | 🔴 **тримай ПОРОЖНІМ**. На CG/рендерах YOLO зве фігуру `kite`, і фільтр `person` викидає ~15 кадрів із 20 (заміряно 08.08) |
| `max_boxes` | скільки боксів лишати на кадрі | 1 якщо об'єкт один |
| `on_miss` | що робити на кадрі без детекції | `previous` — взяти бокс попереднього кадру (SAM2 падає на порожніх кадрах); `full_frame` — весь кадр; `empty` — лишити пустим |
| `make_preview` | малювати картинку з рамками | 🔴 `False` на прогоні. `True` тільки коли підбираєш `conf` на 1–2 кадрах |

**Виходи:** `bounding_box` (формат ядра, у HUD-ноди) · `bbox_for_sam2` (у kijai SAM2) ·
`preview` (порожній 1×1, якщо `make_preview=False`) · `info` (рядок статистики).

## Нода `HUD Sprite (кастомна рамка PNG + дірка)` — `LexHUDSprite`

Бере **зовнішній PNG** із рамкою й садить його на бокс, ведучи за об'єктом.

### Куди ставити рамку

| параметр | що робить |
|---|---|
| `boxes` | бокси з `LexYOLODetect` (вихід `bounding_box`) |
| `mode` | `largest` — найбільший бокс у кадрі (клас ігнорується) · `index` — конкретний за номером · `all` — рамка на КОЖЕН бокс |
| `index` | номер бокса для `mode=index` |
| `offset_x` / `offset_y` | зсунути рамку руками, у пікселях |

### Розмір і пропорція

| параметр | що робить |
|---|---|
| `margin_pct` | 🥇 зазор між боксом і рамкою, у % від середнього розміру бокса. **Однаковий з усіх чотирьох боків** — на вертикальному обличчі рамка огортає рівномірно. Дефолт 25 |
| `margin_px` | той самий зазор, але в пікселях; додається поверх `margin_pct` |
| `aspect` | 🥇 випадайка, не текст. **`box` (дефолт)** = рамка бере форму самого бокса YOLO: обличчя вертикальне — рамка вертикальна, руку зловив квадратом — рамка квадратна. **`png`** = пропорція самого файлу рамки, спрайт масштабується рівномірно й не деформується взагалі. Решта (`1:1`, `4:5`, `9:16`, `16:9`…) форсує пропорцію: коротша сторона **добудовується**, об'єкт не обрізається |
| `min_width` / `min_height` | нижня межа розміру HUD у пікселях кадру — щоб на дрібних боксах рамка не ставала мікроскопічною. 0 = без обмеження |

⚠️ Якщо на **рухомому** об'єкті рамка виглядає зміщеною — це вже не зазор, а `smooth`:
EMA відстає за боксом. Хочеш строго по боксу — `smooth = 0`.
🔴 З `aspect = box` спрайт 3:2 тиснеться у форму бокса, тому `nine_slice` тут **обов'язковий**
(інакше кутовий орнамент розмаже).

### Якість і поведінка

| параметр | що робить |
|---|---|
| `smooth` | 🥇 EMA-згладжування руху рамки. 0 = сирий бокс (сіпається покадрово) · 0.5 дефолт · 0.7–0.8 = дуже плавно, але з відставанням на швидкому русі. Не діє в `mode=all` |
| `nine_slice` | px кутів, які **не розтягувати**. 🔴 Міряється у пікселях **вихідного PNG**, а не кадру — нода сама зменшує кут разом зі спрайтом. Став приблизно розмір кутового кронштейна: для PNG 1536×1024 з кронштейнами ~230 px — **240** |
| `alpha_mode` | звідки брати прозорість: `loadimage` (дефолт — MASK із `LoadImage` **інвертована**, нода це враховує) · `mask_direct` (MASK уже є альфою) · `luma` (яскравість як альфа — для чорно-білих рамок без альфа-каналу) · `opaque` (без прозорості) |
| `tint` | 🥇 перефарбувати рамку. **Тиснеш кнопку `🎨 tint` під полем — відкривається системна піпетка**, hex сідає в поле сам; `✕ без фарбування` очищає. Руками писати `#RRGGBB` теж можна, а ще поле приймає лінк — можна завести `ColorPicker`. Яскравість малюнка зберігається, підмінюється лише відтінок: перегенеровувати PNG через колір не треба |
| `tint_strength` | 0 = оригінал, 1 = повністю у `tint`. Проміжні = підмішування |

### Підпис класу

| параметр | що робить |
|---|---|
| `label` | 🥇 **`auto` (дефолт)** = клас від детектора (`face`, `hand`, `person`) — як у стандартного YOLO. Порожньо = без підпису. Будь-який інший текст пишеться дослівно |
| `label_scale` | розмір відносно висоти рамки. 1.0 дефолт, 0.6 якщо завеликий |
| `label_conf` | дописати впевненість: `face 0.91` |

Колір підпису = `tint`, а якщо `tint` порожній — середній колір самої рамки.
Підпис сідає над рамкою; якщо там не влазить (об'єкт угорі кадру) — переїжджає всередину.
У `hud_only` підпис теж малюється в альфу, тому на прозорій секвенції він є.

🥇 Хочеш, щоб рамка НЕ деформувалась узагалі — постав `aspect = png`: нода сама візьме
пропорцію завантаженого файлу. Тоді спрайт масштабується рівномірно й `nine_slice` майже не потрібен,
але рамка перестане повторювати форму бокса.

### Дірка у відео

| параметр | що робить |
|---|---|
| `hole` | `none` — не чіпати відео · `box` — вирізати сам квадрат YOLO · `hud_rect` — вирізати весь прямокутник HUD |
| `hole_feather` | розмити край дірки, px. 0 = різкий |

### Виходи й RAM

| параметр | що робить |
|---|---|
| `emit` | `composite` (дефолт) — рахувати тільки склеєне · `hud_only` — тільки HUD на прозорому · `both` — обидва, **вдвічі більше RAM** |
| `emit_box_mask` | рахувати ще й маску квадрата. `False` на прогоні |

**Виходи:** `composite` + `composite_alpha` (відео з діркою і рамкою) ·
`hud_rgb` + `hud_alpha` (сама рамка на прозорому, у розмірі відео) ·
`box_mask` · `info` (пише, скільки ГБ виходів рахує).

Вимкнені виходи повертають заглушку 1×1 — не підключай їх нікуди.

## Збереження з прозорістю

```
hud_rgb ─┐
hud_alpha → InvertMask → JoinImageWithAlpha → VHS_VideoCombine
```

🔴 **`InvertMask` обов'язковий.** Ядрова нода `JoinImageWithAlpha` сама робить `alpha = 1.0 - mask`
(`comfy_extras/nodes_compositing.py:207`), а мої альфи вже в нормальній логіці (1 = непрозоро).
Без інверсії дірка вийде навиворіт.

Формат у `VHS_VideoCombine`: **`ProRes`, профіль `4444`** (при наявності альфи ставить
`yuva444p10le`) або `8bit-png` секвенцією.
⚠️ ProRes-пресет VHS жорстко тегає `bt709` — для HUD-графіки байдуже, але HDR/HLG-майстер
через нього не гнати, склеювати в Resolve.

## Нода `Depth Curve (DA3 → вигляд як V2)` — `LexDepthCurve`

**Нащо.** Depth Anything **V2** віддає disparity (≈1/відстань) — нелінійність, що розтягує
ближній план. **V3** віддає ВІДСТАНЬ, а режим `v2_style` у `DA3Render` розтягує її **лінійно**
(`comfy/ldm/depth_anything_3/preprocess.py:93`). На портреті обличчя 1.0–1.3 м при фоні 3 м
займає ~15% тонального діапазону замість ~34% — звідси «V3 пласкіший, хоч і точніший».

Ця нода — арифметика над готовим депсмепом. **Моделі не запускає.** Заміряно:
**32–43 мс/кадр** (512 і FullHD) проти ~16 с інференсу mono_large — тобто **0.2–0.3%** часу.

| параметр | що робить |
|---|---|
| `depth` | вихід `DA3Render` (або будь-який депсмеп-IMAGE) |
| `source` | `near_is_white` — звичайний депсмеп, близьке світле (`v2_style`, `min_max`, ControlNet-депс). `raw_distance` — `DA3Render` у режимі `raw`, де значення = відстань |
| `mode` | 🥇 `disparity` = як у V2 · `gamma` = проста крива · `none` = лише перенормувати |
| `near_bias` | сила нелінійності. ⚠️ **НЕ головна ручка** — див. нижче. Тримай 0.5–1.0, різкий поділ роби рівнями |
| `black_point` / `white_point` | 🥇🎚 **ЛІВИЙ і ПРАВИЙ повзунки Levels з фотошопу.** Ось чим розсуваються провали між планами |
| `gamma` | середній повзунок Levels |
| `clarity` | 🥇 локальний контраст великим радіусом (як повзунок Clarity у фотошопі) — ліплення всередині фігури. 0.3–0.5. ⚠️ Було на CLAHE — знято 10.08, він робив плями, див. нижче |
| `detail` | мікроконтраст (unsharp). 0.3–0.5. ⚠️ від 0.8 малює кільця-контури на плавних градієнтах |
| `deband` | 🥇 прибрати сходинки-полоси, НЕ розмиваючи картинку. Білатеральний фільтр: рівняє дрібні перепади всередині плану, силует лишає різким. Йде ПЕРЕД `clarity`. 0.3–0.5 |
| `deband_edge` | що вважати сміттям, а не межею. 0.06 — тільки полоси · **0.12 дефолт** · 0.2–0.35 бере клоччя на листі, але підточує силует |
| `normalize` | 🥇 **ВІДЕО:** `batch` (дефолт) — чорна/біла точки рахуються ОДИН раз на всю пачку. Саме це прибирає мерехтіння яскравості депсу. `per_frame` — стара поведінка, для одиночних фото |
| `clip_low` / `clip_high` | квантилі обрізання, % (1 / 99 дефолт) |
| `invert` | перевернути, якщо близьке вийшло темним |

**Виходи:** `depth` (IMAGE) · `depth_mask` (MASK) · `info` (пише, де реально лежать тони —
`p2/25/50/75/98`, щоб знати, куди ставити рівні).

### 🔴 Чому `near_bias` не дає контрасту, а тільки гасить картинку

`1/(відстань + bias)` віддає весь тональний бюджет **найближчому** об'єкту. Знижуєш `bias` —
передній план забирає ще більше, а решта злипається біля чорного. Виглядає як «картинка тухне».
Це крива-провал, а не рівні.

**Рівні працюють інакше:** вони не гасять, а **вирізають смугу, де живе сюжет, і розтягують її
на весь діапазон.** Заміряно 10.08.2026 на кадрі з двома фігурами (розмах тонів на тілі
правої фігури, чорний фон виключено):

| | розмах | |
|---|---|---|
| V2, 23.2 с | 0.165 | еталон |
| V3 + `near_bias 0.1` | **0.094** | у 1.8 раза пласкіше — те, що ти бачив оком |
| V3 + рівні 0.22–0.62 + `clarity 0.35` | **0.262** | краще за V2 |
| + `detail 0.8` | 0.294 | 🔴 але вже з кільцями |

⚠️ **Ціна рівнів:** що вужча щілина `black↔white`, то більше планів вилітає в чисте біле й
чисте чорне. На тесті ліва (ближча) фігура вибілилась повністю. Хочеш обидва плани ліпленими —
розширюй щілину й добирай `clarity`.

### Як ставити (мовою фотошопа)

1. `mode` = `disparity`, `near_bias` **0.5–1.0** (або `mode: none`) — м'яка база.
2. Дивись у `info`: `p2/25/50/75/98` каже, у якій смузі лежать тони.
3. `black_point` підіймай, доки фон не провалиться в чорне.
4. `white_point` опускай, доки сюжет не почне вибілюватись — і крок назад.
5. `clarity` 0.3–0.5 — оце дає складки на тканині.
6. `detail` 0.3–0.5 наостанок, не більше.
7. Лізуть полоси — `deband` 0.3–0.5.

### 🔴 Полоси-сходинки: головна причина була в самій ноді

Спіймано 10.08.2026: `clarity` рахувався через **uint8**, тобто CLAHE сама нарізала депсмеп
на 256 сходинок. При вузькій смузі сюжету (0.09 діапазону) це ~23 рівні на все тіло — звідси
«наче 8 біт», і ці смуги тягнулись далі в генерацію. Переведено на **uint16** (65 536 рівнів).

Замір «сходинковості» (99-й перцентиль стрибка / медіана, на гладкому градієнті):

| | |
|---|---|
| чистий градієнт | 1.7 |
| clarity 8 біт + detail 0.5 | **5.0** |
| clarity 16 біт | **2.7** |
| 8 біт + `deband 0.5` | 5.0 |

⚠️ Тобто **`deband` сам по собі 8-бітні смуги НЕ лікує** — їх лікує 16 біт. `deband` потрібен
для решти: сходинок від самої моделі й від сильного розтягу рівнями.

Ланцюг: `LoadDA3Model` (mono_large) → `DA3Inference` → `DA3Render` (`depth`, `v2_style`)
→ **`LexDepthCurve`** → далі у візуалізацію.

🥇 **На V2 ноду теж можна вішати** — але `mode` = **`none`**, бо V2 уже віддає disparity,
і другий раз її накладати означає вдруге зім'яти. Рівні + `clarity` на V2 працюють так само.


### 🔴 Плями-клоччя на фоні і мерехтіння на відео (знято 10.08.2026)

Дві окремі хвороби, обидві були в самій ноді.

**1. Плями.** `clarity` був на CLAHE. CLAHE вирівнює гістограму **в кожній плитці окремо**;
на 1080×1920 плитка виходила 90×160 px, і та, що лягла на рівний фон, розтягувала мікрошум
на весь діапазон — звідси клоччя по кущах і стінах. Замінено на нерізке маскування великим
радіусом (`v + (v − сильно_розмите) × сила`) — це і є справжній Clarity з фотошопа: лінійний,
плям не робить.

**2. Мерехтіння яскравості на відео.** Квантилі 1%/99% рахувались **на кожному кадрі окремо**.
Варто об'єкту зайти чи вийти з кадру — чорна й біла точки їдуть, і вся картинка смикається.
Параметр `normalize = batch` рахує їх один раз на всю пачку. Для `mode: disparity` межі тепер
беруться аналітично (`1/(1+bias)`…`1/bias`), тобто спільні для всіх кадрів завжди.

⚠️ **Чого нода НЕ вилікує.** Клоччя на листі й тонких гілках — це переважно **реальний шум
самої моделі глибини**: тонкі гілки на різній відстані дають спекл. Він видно і на V2,
і на V3. Замір на кадрі 1080×1920: `deband_edge` 0.06 → 0.35 знижує клоччя 0.0397 → 0.0294,
але різкість силуету падає 0.056 → 0.036. Компроміс, а не рішення. Головне — **не підсилювати**:
`detail` тут головний винуватець.

## 🔴 «Об'єм не витягується» + шарп по контуру (знято 10.08.2026)

Дві різні болячки, обидві — мої.

### 1. Ореол по силуету — від бази clarity
`clarity` рахувалась як `v + (v − сильно_розмите) × сила`, а розмиття було **гаусове**.
Гаус розмиває **через межу** фігури, тому біля силуету різниця величезна → світлий кант
зовні, темний усередині. Це і є «край шарпиться».
Замінено на **guided filter** (`cv2.ximgproc.guidedFilter`), який межу не переступає.

| база clarity | ореол біля силуету, \|Δ\| сер | макс | час на 1080×1920 |
|---|---|---|---|
| гаус (було) | 0.102 | 0.459 | 0.068 с |
| guided (стало) | **0.035** | 0.338 | 0.055 с |

Тобто ореол упав утричі й **не подорожчало**. Якщо opencv без contrib — фолбек на
білатерал по зменшеній копії (0.015 с проти 1.4 с у повного білатералу).

### 2. Об'єм плану — `focus` + `focus_strength` (нове)
`black_point`/`white_point` — це Levels: вони інші плани **зрізають** у чорне й біле.
Тому щойно ти розтягував себе (середній план), ноут спереду і будівля ззаду ставали
пласкими плямами — а разом із ними зникало відчуття об'єму сцени.

`focus` — це **Curves**: логістична S-крива навколо обраного тону. Тони свого плану
розтягуються, решта **м'яко стискається**, кінці 0 і 1 крива тримає.

Заміряно на його ж кадрі 1080×1920 (фігура — бокс 700:1500 × 150:800, тон 0.545):

| що | діапазон на фігурі | скільки фону вбито в чорне |
|---|---|---|
| без нічого | 0.529 | 0 % |
| levels 0.55–0.95 | 0.85 | **18 %** |
| focus 0.55 × 4 | 0.626 | 0 % |
| focus 0.55 × 8 | 0.784 | 0 % |
| focus 0.55 × 12 | **0.891** | **0 %** |

S-крива дає **більше** об'єму, ніж Levels, і при цьому не вбиває жодного плану.

**Куди ставити `focus`.** У консоль тепер друкується гістограма планів:
```
[LexDepthCurve] плани 0.0→1.0: | ▁▂▁█▂▄▃▃|  (focus став на потрібний горб)
```
Кожен горб = окремий план сцени. Став `focus` на позицію свого горба (зліва 0.0 = найдалі).

### Рецепт для «виділити себе на середньому плані»
1. `black_point 0.0`, `white_point 1.0` — Levels **не чіпати**, вони для іншого.
2. Подивитись гістограму, поставити `focus` на свій горб.
3. `focus_strength` 4 → 8 → 12, доки план не «встане».
4. `clarity` 0.4–0.7 — ліплення всередині фігури (тепер без канта).
5. `detail` 0.3–0.5 — дрібні складки.

### ⚠️ Чому на V2 з `mode: none` стало гірше, ніж раніше
Раніше `clarity` була CLAHE — вона **вирівнювала гістограму** і сама по собі давала
V2 удар по локальному контрасту (разом із плямами й мерехтінням). Тепер clarity —
чесний локальний контраст, він плям не робить, але й «безкоштовного» розтягу не дає.
Той розтяг тепер живе в `focus_strength` — на V2 його теж треба вмикати.
